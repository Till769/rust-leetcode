## 1. Copy List with Random Pointer (Medium) – in Go

- **Muster:** Hashing / Identitäts-Map: alter Knoten (Pointer) → neuer Knoten, dazu zwei Durchläufe (erst anlegen, dann verlinken).
- **Hinweisstufe benötigt:** 4, aber nur wegen der Go-Syntax. Den Algorithmus habe ich mit Stufe 1 gefunden. Die Leitfrage „Muss `random` im selben Durchlauf gesetzt werden wie `next`?“ brachte mich auf die zwei Durchläufe, Map-Schlüssel und Map-Wert habe ich selbst bestimmt. Für den Code gab es ein Skelett mit Lücken.
- **Komplexität:** Zeit O(n) (zwei Durchläufe), Speicher O(n) zusätzlich für die Map (die Ausgabeliste nicht mitgezählt)
- **Status:** Tests auf LeetCode grün, Einreichung nicht ausdrücklich bestätigt
- **Wiederholen am:** 2026-11-03, dann 2026-11-07, dann 2026-11-30. Beim ersten Mal ohne Skelett in Go schreiben.

### Aufgabe

Gegeben ist eine verkettete Liste, in der jeder Knoten zusätzlich einen `random`-Pointer auf einen beliebigen Knoten der Liste oder auf `null` hat. Gesucht ist eine Deep Copy aus genau n neuen Knoten. `next` und `random` der Kopie dürfen nur auf neue Knoten zeigen, nie auf Knoten des Originals.

Die Ein-/Ausgabe `[[val, random_index], ...]` ist nur die Textdarstellung der Testfälle. Der Code bekommt den echten `head` mit Pointern, keine Indizes.

**Constraints:** `0 <= n <= 1000`, `-10^4 <= val <= 10^4`.

Beispiele: `[[7,null],[13,0],[11,4],[10,2],[1,0]]`, `[[1,1],[2,1]]`, `[[3,null],[3,0],[3,null]]` (Ausgabe jeweils identisch).

Rust wird für diese Aufgabe von LeetCode nicht angeboten, deshalb habe ich sie in Go gelöst.

### Kernidee (eigene Worte)

> Man kopiert die Knoten erstmal und mapt sie in einer Hash-Map mit dem alten Knoten als Schlüssel und den neuen als Wert. Dann läuft man ein zweites Mal über die Liste und ermittelt über die alte Liste und die Map die Knoten zum Verlinken.

### Weg zur Lösung

1. **Aufgabe verstehen:** Was ist das Besondere am Random-Pointer? Er zeigt auf einen alten Knoten, die Kopie muss aber auf die passende *neue* Kopie zeigen. Das `[val, random_index]`-Format war zunächst verwirrend, es ist aber nur die Darstellung der Testdaten.
2. **Beispiel 3** (alle Werte gleich 3) zeigt: Man darf nicht nach Werten suchen, es zählt die Identität des Knotens.
3. **Erste Analyse in einem Durchlauf:** drei Fälle. `random == nil`, Ziel liegt davor (existiert schon) und Ziel liegt dahinter (existiert noch nicht, Verlinkung müsste man sich merken). Der dritte Fall wird kompliziert, außerdem gibt es keine Indizes, nur Pointer.
4. **Entscheidende Erkenntnis:** Mit zwei Durchläufen fällt der dritte Fall weg. Erst alle Knoten anlegen, dann verlinken, denn im zweiten Durchlauf existieren alle Kopien. Ohne Hilfsstruktur müsste man für jeden Knoten erneut über die Liste laufen, also O(n²).
5. **Map:** alter Knoten → neuer Knoten. Im zweiten Durchlauf liefert `alt2neu[cur.Random]` direkt die neue Kopie.
6. **Go-Detail:** Ein fehlender Schlüssel (auch `nil`) liefert den Nullwert `nil`. Dadurch braucht man keine Sonderfälle für das Listenende, für `Random == nil` und für eine leere Liste.

### Meine Lösung

Erste Fassung: Im ersten Durchlauf wurden `Next` und `Random` noch auf die alten Knoten gesetzt.

```go
func copyRandomList(head *Node) *Node {
    alt2neu := make(map[*Node]*Node)

    // 1. Durchlauf: zu jedem alten Knoten eine Kopie anlegen und merken
    for cur := head; cur != nil; cur = cur.Next {
        // Kopie mit gleichem Val anlegen und in alt2neu eintragen
        neu := &Node{Val: cur.Val, Next: cur.Next, Random: cur.Random}
        alt2neu[cur] = neu
    }

    // 2. Durchlauf: Next und Random der Kopien setzen
    for cur := head; cur != nil; cur = cur.Next {
        kopie := alt2neu[cur]
        kopie.Next = alt2neu[cur.Next]
        kopie.Random = alt2neu[cur.Random]
    }

    return alt2neu[head]
}
```

Endgültige Fassung (Tests grün):

```go
func copyRandomList(head *Node) *Node {
    alt2neu := make(map[*Node]*Node)

    for cur := head; cur != nil; cur = cur.Next {
        neu := &Node{Val: cur.Val}
        alt2neu[cur] = neu
    }

    for cur := head; cur != nil; cur = cur.Next {
        kopie := alt2neu[cur]
        kopie.Next = alt2neu[cur.Next]
        kopie.Random = alt2neu[cur.Random]
    }

    return alt2neu[head]
}
```

Vergleich: Die alten Pointer im ersten Durchlauf waren überflüssig, weil sie im zweiten Durchlauf überschrieben werden. Sie waren auch riskant: Bei einer vergessenen Zuweisung hätte die Kopie stillschweigend in die Originalliste gezeigt. Mit `&Node{Val: cur.Val}` würde ein solcher Fehler als `nil` auffallen.

**Offen (Alternative):** Geht es mit O(1) zusätzlichem Speicher, also ohne Map? Leitfrage: Wo kann man die Kopie ablegen, damit man sie vom alten Knoten aus mit einem einzigen Pointer-Schritt erreicht?

### Wo ich hing

- Das Ein-/Ausgabeformat `[val, random_index]`: Mir war nicht klar, dass das nur die Darstellung der Testfälle ist.
- In einem Durchlauf denken: Den Fall „Ziel existiert noch nicht“ wollte ich mit gemerkten offenen Verlinkungen lösen, statt das Problem in zwei Durchläufe aufzuteilen.
- Go-Syntax (Schleife, Map, Knoten anlegen): Dafür brauchte ich ein Skelett mit Lücken.
- LeetCode-Fehler `Node redeclared in this block`: Ich hatte das `type Node struct` mit eingefügt, LeetCode definiert es aber selbst.
- Wortwahl: Die Pointer zeigen auf die alten Knoten (Heap), nicht auf den Stack.

### Go-Learnings (statt Rust)

- Go kennt kein `while`. Man schreibt `for cond { ... }` oder die Kurzform `for cur := head; cur != nil; cur = cur.Next { ... }`.
- `&Node{Val: x}` legt eine Struct an und liefert einen Pointer. Nicht gesetzte Felder sind `nil`.
- `make(map[*Node]*Node)`: Pointer als Map-Schlüssel vergleichen nach Adresse, also nach Identität.
- `m[k]` mit fehlendem Schlüssel liefert den Nullwert des Typs (bei Pointern `nil`) statt eines Fehlers. Das spart Sonderfälle.
- `:=` deklariert eine Variable, `=` weist zu.
- Für LeetCode schickt man nur die Funktion ab, keine Typdefinitionen und kein `main`.
- Warum Rust hier schwer ist: Mehrere Pointer auf denselben Knoten bräuchten `Rc<RefCell<…>>`. Go hat einen Garbage Collector und echte Pointer.
