# Lerntagebuch – 2026-10-18

## 520. Detect Capital (Easy)

- **Muster:** Ein Durchlauf mit Flags; danach als Iterator-Ausdruck mit `all` / `any`
- **Hinweisstufe benötigt:** 0 (nur Gegenfragen und Gegenbeispiele. Auf Nachfrage gab es eine allgemeine Erklärung, wie man in Rust über einen String iteriert: `chars`, `bytes`, `enumerate`, `skip`, `all`/`any`)
- **Komplexität:** Zeit O(n), Speicher O(1)
- **Status:** lokale Tests grün (9 Tests), Einreichung offen
- **Wiederholen am:** 2026-10-21, dann 2026-10-25, dann 2026-11-18

### Aufgabe

Die Großschreibung eines Wortes ist richtig, wenn einer dieser Fälle gilt: alle Buchstaben groß (`"USA"`), alle klein (`"leetcode"`) oder nur der erste groß (`"Google"`). Gib `true` zurück, wenn `word` richtig geschrieben ist.

**Constraints:** `1 <= word.length <= 100`, nur englische Groß- und Kleinbuchstaben.

Beispiele: `"USA"` → true, `"FlaG"` → false. Weitere Testfälle: `"leetcode"`, `"Google"`, `"g"`, `"G"` → true; `"gOOGLE"`, `"leetcodE"`, `"GOogle"` → false.

### Kernidee (eigene Worte)

> Man läuft über den String und prüft, ob alle Buchstaben groß sind oder es nach dem ersten Buchstaben noch einen Großbuchstaben gab. Das reicht für die drei gültigen Optionen.

**Schärfung:** Gültig ist das Wort, wenn alle Buchstaben groß sind **oder nach dem ersten Buchstaben *kein* Großbuchstabe mehr kommt**. Im Satz fehlt die Verneinung, also genau das `!`, das auch im ersten Einzeiler fehlte. Der zweite Teil deckt „alle klein“ und „nur der erste groß“ gemeinsam ab, weil der erste Buchstabe dafür keine Rolle spielt.

### Weg zur Lösung

1. **Erste Annahme:** Nur zwei gültige Fälle (alle groß, nur der erste groß). Mit `"leetcode"` und `"g"` den dritten Fall „alle klein“ selbst gefunden.
2. **Ausgangsfrage:** Über den String laufen oder gültige Kandidaten bauen und vergleichen? Kandidatenansatz durchdacht: Der erste Buchstabe bestimmt, welche Kandidaten in Frage kommen (bei `"FlaG"` nur `"Flag"` und `"FLAG"`). Beide Ansätze laufen in O(n) Zeit, der Kandidatenansatz braucht aber O(n) Speicher, der Durchlauf nur O(1).
3. **Benötigte Information beim Durchlauf:** Ob alle groß sind (Flag startet mit `true`, kippt beim ersten Kleinbuchstaben) und ob nach dem ersten Buchstaben noch ein Großbuchstabe kam.
4. **Tabelle mit drei Variablen** (Anfangsbuchstabe, alle groß, noch Großbuchstabe) für fünf Beispiele aufgestellt. Erkenntnis: Für „alle klein“ und „nur vorne groß“ ist der Anfangsbuchstabe egal. Daraus folgt `alle_groß || !noch_großbuchstabe`.
5. **Code:** Erste Fassung schlug bei `"GOogle"` fehl, weil das Flag in jeder Iteration neu zugewiesen und damit wieder überschrieben wurde. Mit einem `if` davor selbst behoben.
6. **Umbau auf Iteratoren:** `all` für „jedes Zeichen“, `skip(1).any` für „mindestens eins ab Index 1“. Beim Einsetzen fehlte zunächst das `!`, 7 Tests rot. Danach `return` durch den Schlussausdruck ersetzt.

### Meine Lösung

Fassung 1, Schleife mit Flags (alle Tests grün):

```rust
impl Solution {
    pub fn detect_capital_use(word: String) -> bool {
        let mut alle_groß = true;
        let mut noch_großbuchstaben = false;

        for (i, c) in word.char_indices() {
            if c.is_lowercase() && alle_groß {
                alle_groß = false;
            }
            if !noch_großbuchstaben {
                noch_großbuchstaben = i > 0 && c.is_uppercase();
            }
        }
        return alle_groß || !noch_großbuchstaben;
    }
}
```

Fassung 2, Iteratoren (Endfassung, alle Tests grün):

```rust
impl Solution {
    pub fn detect_capital_use(word: String) -> bool {
        word.chars().all(|c| c.is_uppercase()) || !word.chars().skip(1).any(|c| c.is_uppercase())
    }
}
```

Vergleich: Beide Fassungen brauchen O(n) Zeit und O(1) Speicher. Die Schleife läuft immer bis zum Ende. Die Iterator-Fassung läuft im schlechtesten Fall zweimal über das Wort, bricht aber früh ab: `all` beim ersten `false`, `any` beim ersten `true`, und `||` wertet die rechte Seite nur aus, wenn links `false` steht.

Offene Ideen: `is_ascii_uppercase()` statt `is_uppercase()` (laut Constraints nur A–Z, etwas günstiger); alternative Lösung durch Zählen der Großbuchstaben ausprobieren.

### Wo ich hing

- Anfangs nur zwei gültige Fälle gesehen, „alle klein“ übersehen.
- Flag per `=` in jeder Iteration überschrieben statt nur einmal zu setzen. Gefunden durch Nachverfolgen von `"GOogle"`.
- Beim Ersetzen der Variablen durch die Iterator-Ausdrücke die Verneinung `!` vergessen.

### Rust-Learnings

- `String` ist UTF-8, deshalb gibt es kein `word[i]`. Iteriert wird mit `.chars()`, `.bytes()` oder `.char_indices()` (liefert `(Byte-Index, char)`).
- `.all()` und `.any()` verbrauchen den Iterator und geben ein `bool` zurück. Man kann sie nicht hintereinanderketten, aber `word.chars()` beliebig oft neu aufrufen, weil es nur ausleiht.
- `.skip(1)` überspringt das erste Element.
- `||` wertet kurzschließend aus: Ist die linke Seite `true`, läuft die rechte gar nicht.
- Der letzte Ausdruck ohne Semikolon ist der Rückgabewert eines Blocks. `return` braucht man idiomatisch nur für einen vorzeitigen Ausstieg.
- `char::is_uppercase()` kennt Unicode, `is_ascii_uppercase()` nur A–Z.
