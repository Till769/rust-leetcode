# Lerntagebuch – 2026-10-20

## 831. Masking Personal Information (Medium)

- **Muster:** Fallunterscheidung nach Eingabeform, dann String-Bereinigung per Iterator-Kette und Neuaufbau des Ergebnisses mit `format!`
- **Hinweisstufe benötigt:** 2 (Stufe 2 bei „Wie komme ich an die Ziffern?“ mit Verweis auf `chars()`/`is_uppercase` aus 520 und auf `filter`, Stufe 2 bei `split_once` statt `split`, Stufe 1 beim Maskieren des Namens: „Vom Original überleben nur zwei Zeichen“. Dazu mehrere allgemeine Erklärungen zu Rust-Sprachmitteln: `Pattern`, `next()`, Ausdrücke vs. `return`)
- **Komplexität:** Zeit O(n), Speicher O(n)
- **Status:** eingereicht und bestanden, lokale Tests grün (11 Tests)
- **Wiederholen am:** 2026-10-23, dann 2026-10-27, dann 2026-11-20

### Aufgabe

`s` ist entweder eine E-Mail-Adresse oder eine Telefonnummer und soll maskiert werden.

- **E-Mail:** Name (≥ 2 Buchstaben) `@` Domain (Buchstaben mit einem `.` in der Mitte). Alles kleinschreiben, die Mitte des Namens durch genau fünf `*` ersetzen.
- **Telefon:** 10–13 Ziffern, getrennt durch beliebige Zeichen aus `{'+', '-', '(', ')', ' '}`. Die letzten 10 Ziffern sind die lokale Nummer, die 0–3 davor die Ländervorwahl. Ausgabe `***-***-XXXX`, mit Ländervorwahl `+*-`, `+**-` oder `+***-` davor. `XXXX` sind die letzten vier Ziffern.

**Constraints:** `s` ist immer gültig. E-Mail: Länge 8–40, genau ein `@` und ein `.`. Telefon: Länge 10–20.

Beispiele: `"LeetCode@LeetCode.com"` → `"l*****e@leetcode.com"`; `"AB@qq.com"` → `"a*****b@qq.com"`; `"1(234)567-890"` → `"***-***-7890"`. Weitere Testfälle: `"(12) 345-678-90"` → `"***-***-7890"`, `"+1 (234) 567-8901"` → `"+*-***-***-8901"`, `"+86-(10)123456789"` → `"+***-***-***-6789"`.

### Kernidee (eigene Worte)

> Keine besondere Logik, viele String-Operationen, die man elegant mit Rust lösen kann.

**Schärfung:** Stimmt als Einordnung. Drei kleine Entscheidungen tragen die Lösung trotzdem: (1) Der Typ ist am ersten Zeichen erkennbar, **Buchstabe → E-Mail**, aber nicht umgekehrt „`+` oder Ziffer → Telefon“, weil eine Nummer auch mit `(` oder Leerzeichen beginnen kann. (2) Die Länge der Ländervorwahl ist **Anzahl Ziffern − 10**. (3) Der maskierte Name wird **neu gebaut** aus erstem Zeichen + `*****` + letztem Zeichen, nicht im Original ersetzt.

### Weg zur Lösung

1. **Erste Einschätzung:** Fleißaufgabe ohne algorithmischen Trick. Das trifft zu, der Lerneffekt liegt in Rust.
2. **Typ erkennen:** Erste Regel „beginnt mit `+` oder Ziffer → Telefon“. Am Gegenbeispiel `"(12) 345-678-90"` gekippt, umgedreht zu „beginnt mit Buchstabe → E-Mail“.
3. **Ländervorwahl:** 10/11/12/13 Ziffern → 0/1/2/3 Stellen. Gebraucht werden nur diese Anzahl und die letzten vier Ziffern.
4. **Ziffern sammeln:** `s.chars().filter(|c| c.is_ascii_digit())`.
5. **E-Mail:** `to_ascii_lowercase`, dann `split_once('@')`. Beim Maskieren hing es, bis klar war, dass nur erstes und letztes Zeichen übrig bleiben. Diese kommen per `next()` bzw. `last()`.
6. **Compiler:** `return "";` hinter dem `if` und ein leerer `else`-Zweig. Gelöst, indem `if`/`else` zum letzten Ausdruck der Funktion wurde.
7. **Review:** `last()` → `next_back()`, `match` mit Zuweisung in jedem Arm → `let country_mask = match … { … };`.

### Meine Lösung

Erste grüne Fassung:

```rust
impl Solution {
    pub fn mask_pii(s: String) -> String {
        if s.starts_with(|c: char| c.is_ascii_alphabetic()) {
            let email: String = s.to_ascii_lowercase();
            let (name, domain) = email.split_once('@').unwrap();
            let first_name = name.chars().next().unwrap();
            let last_name = name.chars().last().unwrap();
            format!("{first_name}*****{last_name}@{domain}")
        } else {
            let mut numbers: String = s.chars().filter(|c| c.is_ascii_digit()).collect();
            let country_code = numbers.len() - 10;
            let country_mask;
            match country_code {
                0 => country_mask = "",
                1 => country_mask = "+*-",
                2 => country_mask = "+**-",
                3 => country_mask = "+***-",
                _ => unreachable!(),
            }
            let number_last = numbers.split_off(numbers.len() - 4);
            format!("{country_mask}***-***-{number_last}")
        }
    }
}
```

Endfassung nach Review (eingereicht):

```rust
impl Solution {
    pub fn mask_pii(s: String) -> String {
        if s.starts_with(|c: char| c.is_ascii_alphabetic()) {
            let email: String = s.to_ascii_lowercase();
            let (name, domain) = email.split_once('@').unwrap();
            let first_name = name.chars().next().unwrap();
            let last_name = name.chars().next_back().unwrap();
            format!("{first_name}*****{last_name}@{domain}")
        } else {
            let mut numbers: String = s.chars().filter(|c| c.is_ascii_digit()).collect();
            let country_code = numbers.len() - 10;
            let country_mask = match country_code {
                0 => "",
                1 => "+*-",
                2 => "+**-",
                3 => "+***-",
                _ => unreachable!(),
            };
            let number_last = numbers.split_off(numbers.len() - 4);
            format!("{country_mask}***-***-{number_last}")
        }
    }
}
```

Vergleich: Komplexität gleich. `next_back()` holt das letzte Zeichen in O(1) statt über den ganzen Namen zu laufen. Das `match` als Ausdruck macht `country_mask` zu einer gewöhnlichen, sofort initialisierten Bindung.

Offene Ideen: `country_mask` ohne Fallunterscheidung über `"*".repeat(country_code)` bauen, mit `0` als Sonderfall; `name`/`first_name`/`last_name` heißen eigentlich erstes/letztes *Zeichen* des Namens, eine Umbenennung wäre lesbarer.

### Wo ich hing

- Typerkennung zuerst über „`+` oder Ziffer“, Gegenbeispiel `"(12) 345-678-90"`.
- Wie man an die Ziffern kommt, war unklar, bis der Bezug zu `chars()` + `is_uppercase` aus 520 kam.
- `char::is_ascii_alphabetic(&self)` als Pattern für `starts_with` versucht.
- Den Namen „unkenntlich machen“ als Ersetzen gedacht statt als Neuaufbau.
- Dachte, `format!` liefere keinen Rückgabewert. Das eigentliche Problem war `return "";` nach dem `if` und der leere `else`-Zweig.
- Methode für das erste Element eines Iterators gesucht (`first` gibt es nicht).
- Nach dem Umbau auf `let … = match` fehlte das Semikolon.

### Rust-Learnings

- `is_numeric()` (Unicode, weit gefasst), `is_digit(radix)` (mit Basis) und `is_ascii_digit()` (genau `'0'..='9'`) sind verschieden. Für ASCII-Eingaben drückt `is_ascii_digit()` die Absicht am klarsten aus.
- `filter` übergibt der Closure `&char`. Methodenaufrufe dereferenzieren automatisch.
- `str::starts_with` akzeptiert jedes `Pattern`: `char`, `&str`, `[char; N]` oder eine Closure `|c: char| -> bool`. Die Closure bekommt `char` per Wert, daher passt `char::is_ascii_alphabetic` (nimmt `&self`) nicht direkt, wohl aber z. B. `char::is_alphabetic` (nimmt `self`).
- `char::to_lowercase()` liefert einen Iterator, kein `char`, weil manche Zeichen kleingeschrieben zu mehreren werden. `str::to_ascii_lowercase()` / `str::to_lowercase()` arbeiten direkt auf dem ganzen String.
- `split_once(c)` liefert `Option<(&str, &str)>` und lässt sich direkt destrukturieren.
- Am `Iterator` gibt es kein `first()`: Das erste Element ist `next()`. `last()` verbraucht den Iterator. `chars()` ist doppelseitig, daher holt `next_back()` das letzte Zeichen in O(1).
- Blöcke, `if`/`else` und `match` sind Ausdrücke. Ihr Wert ist der letzte Ausdruck ohne Semikolon, ein leerer Block hat den Typ `()`. `return` braucht man nur zum vorzeitigen Aussteigen. Beide Zweige müssen denselben Typ haben, und `""` ist `&str`, nicht `String`.
- `let x = match … { … };` braucht das Semikolon, weil es eine `let`-Anweisung ist.
- „Erst deklarieren, dann in jedem Zweig zuweisen“ ist ein Hinweis darauf, dass `match`/`if` als Ausdruck besser passt.
- `String::len()` zählt Bytes und ist O(1). Bei ASCII entspricht das der Zeichenzahl.
- `String::split_off(i)` schneidet ab Byte `i` ab und gibt den Rest als neuen `String` zurück.
- `unreachable!()` dokumentiert einen Fall, den die Constraints ausschließen.
