## 739. Daily Temperatures (Medium)

- **Muster:** Monotonic Stack (fallend bzgl. Temperatur, Indizes auf dem Stack)
- **Hinweisstufe benötigt:** 0 für den Algorithmus (Ansatz komplett selbst). Rust-Review: Stufe 2 (Let-Chains und `&&`-Kurzschluss als Werkzeuge genannt). Dazu Setup-Hilfe für das lokale Cargo-Projekt, Testgerüst vorgegeben.
- **Komplexität:** Zeit O(n) (amortisiert), zusätzlicher Speicher O(n) (Stack)
- **Status:** lokal kompiliert, alle Tests bestanden; Einreichung bei LeetCode noch nicht bestätigt

### Aufgabe

Gegeben ist ein Array `temperatures` mit Tagestemperaturen. Gesucht ist `answer`, wobei `answer[i]` die Anzahl der Tage ist, die man nach Tag `i` auf eine wärmere Temperatur warten muss. Gibt es keinen solchen Tag, ist `answer[i] = 0`.

**Constraints:** `1 <= temperatures.length <= 10^5`, `30 <= temperatures[i] <= 100`

| Eingabe | Ausgabe |
|---|---|
| `[73,74,75,71,69,72,76,73]` | `[1,1,4,2,1,1,0,0]` |
| `[30,40,50,60]` | `[1,1,1,0]` |
| `[30,60,90]` | `[1,1,0]` |

### Kernidee (eigene Worte)

> Nutzung des Monotonic Stacks und dort die Indizes der Temperaturen speichern. Damit kann man dann die noch nicht verarbeiteten Werte abarbeiten, die die Bedingung erfüllen. Da man die Indizes speichert, kann man gleich den Abstand der Tage berechnen.

**Schärfung:** „Die Bedingung“ konkret: Der aktuelle Tag ist **echt wärmer** (`>`) als der oberste wartende Tag – und weil er der *erste* wärmere Tag ist, den dieser Tag erlebt, ist die Differenz `idx - last` sofort die endgültige Antwort. Daraus folgt, dass der Stack in den Temperaturen immer (nicht streng) fallend ist. Und: Tage, die am Ende noch auf dem Stack liegen, brauchen keine Behandlung, weil `answer` mit 0 vorbelegt ist.

### Weg zur Lösung

1. **Mustererkennung:** Sofort als Verwandte von 1475 (Final Prices, gestern) erkannt: Wartende Elemente liegen auf dem Stack, jeder neue Wert bedient von oben alle, die er erfüllt.
2. **Indizes statt Werte:** Gesucht ist ein Abstand, also braucht man die Position – den Wert holt man sich über `temperatures[last]`.
3. **Handsimulation** von Beispiel 1 – dabei in Schritt 5 zunächst vergessen, die 5 zu pushen (Stack danach `[2,5]`, nicht `[2]`).
4. **Komplexität:** `while` in `for`, aber jeder Index wird höchstens einmal gepusht und gepoppt → amortisiert O(1) pro Element, O(n) gesamt. Speicher-Worst-Case: streng fallende Temperaturen, alle n Indizes liegen auf dem Stack.

### Meine Lösung

Erste lauffähige Fassung:

```rust
impl Solution {
    pub fn daily_temperatures(temperatures: Vec<i32>) -> Vec<i32> {
        let mut stack: Vec<usize> = Vec::with_capacity(temperatures.len());
        let mut answer: Vec<i32> = vec![0; temperatures.len()];
        for t in 0..temperatures.len() {
            while let Some(&last) = stack.last() {
                if temperatures[t] > temperatures[last] {
                    answer[last] = (t - last) as i32;
                    stack.pop();
                } else {
                    break;
                }
            }
            stack.push(t);
        }
        answer
    }
}
```

Finale Fassung (Let-Chain + `enumerate`):

```rust
impl Solution {
    pub fn daily_temperatures(temperatures: Vec<i32>) -> Vec<i32> {
        let mut stack: Vec<usize> = Vec::with_capacity(temperatures.len());
        let mut answer: Vec<i32> = vec![0; temperatures.len()];
        for (idx, &temp) in temperatures.iter().enumerate() {
            while let Some(&last) = stack.last()
                && temp > temperatures[last]
            {
                answer[last] = (idx - last) as i32;
                stack.pop();
            }
            stack.push(idx);
        }
        answer
    }
}
```

Vergleich: Logik identisch. Die finale Fassung bündelt die Abbruchbedingung im Schleifenkopf (kein `if`/`else`/`break` mehr), und `enumerate` liefert Index und Wert in einem Schritt, sodass der Vergleich wie die Aufgabenstellung liest.

**Offene Idee (Alternative):** Geht es ohne Stack, nur mit `answer` und O(1) Extraspeicher? Richtung: Array von hinten durchlaufen und bereits berechnete `answer[j]` als Sprungweite nutzen, um nicht-wärmere Tage zu überspringen.

### Rust-Learnings

- `rustup update` aktualisiert die Toolchain; `cargo init --lib` legt ein Projekt im aktuellen Ordner an (`cargo new` dagegen einen Unterordner).
- Projektstruktur: ein Lib-Crate, pro Aufgabe ein Modul (`src/p0739_daily_temperatures.rs`), eingebunden in `lib.rs` mit `pub mod …;`.
- Tests in `#[cfg(test)] mod tests { use super::*; … }`; `cargo test p0739` filtert nach Namen; `todo!()` als kompilierbarer Platzhalter.
- Assoziierte Funktionen (in `impl Typ`) ruft man mit `Typ::funktion()` auf – wie `Vec::new()`.
- `as` konvertiert zwischen Zahlentypen; hier sicher, weil der Abstand < 10^5 immer in `i32` passt.
- **Let-Chains** (ab Rust 1.88, `edition = "2024"`): `while let Some(&x) = v.last() && bedingung { … }` verbindet Muster und Bedingung in einem Kopf. Alternative ohne Let-Chain: `&&`-Kurzschluss mit einer Leerprüfung links.
- `iter().enumerate()` mit Muster `(idx, &val)` liefert Index und kopierten Wert gleichzeitig.
