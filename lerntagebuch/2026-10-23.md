# Lerntagebuch – 2026-10-23

## 686. Repeated String Match (Medium)

- **Muster:** Wiederholungs-/Rotations-Trick mit Längenschranke – `b` liegt in `a` wiederholt `⌈|b|/|a|⌉` oder `⌈|b|/|a|⌉ + 1` Mal, sonst nie
- **Hinweisstufe benötigt:** 2 (Grundidee „wiederholen + `contains`“ selbst; Fehler bei `b/a + 1` am Gegenbeispiel `"abc"`/`"cabca"` selbst gefunden; Stufe 1 für „aufrunden“ und „wo kann `b` in `a` frühestens/spätestens anfangen“; `div_ceil` als Methode direkt genannt bekommen (Stufe 2); obere Schranke `n + 1` danach selbst abgeleitet)
- **Komplexität:** Zeit O(|a| + |b|) (`str::contains` mit Two-Way, linear in Text + Muster), Speicher O(|a| + |b|) – `aa` wird höchstens `|b| + 2·|a| − 1` lang
- **Status:** eingereicht und bestanden
- **Wiederholen am:** 2026-10-26, dann 2026-10-30, dann 2026-11-23

### Aufgabe

Gegeben zwei Strings `a` und `b`. Gib die minimale Anzahl zurück, wie oft `a` wiederholt werden muss, damit `b` ein Teilstring davon ist; ist das unmöglich, `-1`. (`a` 0-mal wiederholt ist `""`.)

**Constraints:** `1 <= a.length, b.length <= 10^4`, nur Kleinbuchstaben.

Beispiele: `"abcd"`, `"cdabcdab"` → `3`; `"a"`, `"aa"` → `2`. Eigene Testfälle: `"abc"`, `"cabca"` → `3`; `"abc"`, `"abd"` → `-1`.

### Kernidee (eigene Worte)

> Kernidee ist, den String a für den minimalen und maximalen Fall zu wiederholen und zu prüfen, ob b in einem davon auftaucht. Der minimale Fall ist b/a und das Ergebnis aufrunden, der maximale Fall ist, a nochmal weiter dranzuhängen. Das muss man machen, wenn b später in a anfängt.

**Schärfung:** Gemeint sind die Längen (`b.len() / a.len()`, aufgerundet). Und der Grund, warum *eine* zusätzliche Kopie reicht: `b` beginnt spätestens beim letzten Zeichen der ersten Kopie, es werden also höchstens `a.len() − 1` Zeichen „verschenkt“ – weniger als eine ganze Kopie. Ist `b` auch in `n + 1` Kopien nicht enthalten, ist es nie enthalten → `-1`.

### Weg zur Lösung

1. **Erster Ansatz:** `n = b.len() / a.len()`, dann `n + 1` Kopien und `contains`. Gibt aber nur ja/nein, nicht das Minimum.
2. **Gegenbeispiel `"abc"`/`"cabca"`:** `5/3 = 1` → `"abcabc"` enthält `b` nicht, es braucht 3 Kopien. Ganzzahldivision rundet ab, und `b` kann mitten in `a` beginnen.
3. **Minimum:** Aufrunden statt abrunden → `div_ceil`. (`b/a + 1` scheitert bei Vielfachen, z. B. `"abc"`/`"abcabc"`.)
4. **Maximum:** `b` startet spätestens beim letzten Zeichen von `a` → höchstens eine Kopie mehr, also `n + 1`.
5. **Ablauf:** Erst `n` prüfen (liefert das Minimum), dann eine Kopie anhängen und `n + 1` prüfen, sonst `-1`.

### Meine Lösung

```rust
impl Solution {
    pub fn repeated_string_match(a: String, b: String) -> i32 {
        let n = b.len().div_ceil(a.len());
        let mut aa = a.repeat(n);
        if aa.contains(&b) {
            return n as i32;
        }
        aa.push_str(a.as_str());
        if aa.contains(&b) {
            return n as i32 + 1;
        }
        -1
    }
}
```

`push_str` hängt nur eine Kopie an, statt mit `repeat(n + 1)` einen neuen String zu bauen.

Offene Idee (noch nicht umgesetzt): Die doppelte Prüfung als Iterator über `n..=n + 1` mit `find` und einer `map…`-Methode von `Option` ausdrücken – kürzer, aber vermutlich ohne den `push_str`-Vorteil.

### Rust-Learnings

- `usize::div_ceil` (seit Rust 1.73) für Ganzzahldivision mit Aufrunden.
- `str::contains` erwartet ein generisches `P: Pattern`; `Pattern` ist u. a. für `&str`, `char`, Closures **und `&String`** implementiert – deshalb geht `contains(&b)` statt `contains(b.as_str())`. Deref-Coercion greift bei generischen Parametern nicht.
- `Iterator::find` liefert das erste passende Element als `Option` (`Some`/`None`).
- `n as i32` ist hier sicher, weil die Constraints die Länge auf 10⁴ begrenzen.
- Verwandt mit 796 und 459: wieder der „String wiederholen + `contains`“-Trick.
