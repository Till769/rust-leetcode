# Lerntagebuch – 2026-10-29

## 1. Two Sum (Easy)

- **Muster:** Hashing / Komplement-Lookup: Statt den Partner zu suchen, rechnet man ihn aus (`y = target - x`) und schlägt ihn in O(1) in einer HashMap nach.
- **Hinweisstufe benötigt:** 1. Der Perspektivwechsel „aus x und target lässt sich y direkt ausrechnen“ kam als Leitfrage. Die HashMap als Werkzeug, Wert als Key und Index als Value, den Sonderfall „gleicher Index“ und das Überschreiben bei Duplikaten habe ich selbst gefunden.
- **Komplexität:** Zeit O(n) (zwei Durchläufe), Speicher O(n)
- **Status:** kompiliert, Tests lokal grün, Einreichung offen. Die letzte Zeile nach der Schleife (`vec![]` oder `unreachable!()`) war beim Abschluss noch offen.
- **Wiederholen am:** 2026-11-01, dann 2026-11-05, dann 2026-11-29

### Aufgabe

Gegeben sind ein Array `nums` und ein `target`. Gesucht sind die Indizes der zwei Zahlen, deren Summe `target` ergibt. Es gibt genau eine Lösung, und kein Element darf doppelt verwendet werden. Die Reihenfolge der Antwort ist egal.

**Constraints:** `2 <= n <= 10^4`, Werte und `target` zwischen `-10^9` und `10^9`. Follow-up: schneller als O(n²).

Beispiele: `[2,7,11,15], 9` → `[0,1]`; `[3,2,4], 6` → `[1,2]`; `[3,3], 6` → `[0,1]`.

### Kernidee (eigene Worte)

> Man hat die Liste in eine HashMap kopiert. Dann läuft man über die Liste und schaut für jeden Wert x, was für einen Wert y man bräuchte. Diesen Wert sucht man in der HashMap als Key und bekommt, wenn es den gibt, den Index zurück. Wenn dieser ungleich dem aktuellen Index ist, mit dem man über die Liste läuft, hat man das Ergebnis gefunden.

**Schärfung:** Der eigentliche Trick ist das Umdrehen der Frage. Statt „Passt x zu irgendeinem y?“ (alle y durchprobieren, O(n²)) fragt man „Gibt es genau den Wert `target - x`?“. Das ist ein einziger O(1)-Lookup. Die HashMap ist nur das Werkzeug dafür.

### Weg zur Lösung

1. **Erste Idee:** Liste sortiert in eine HashMap legen und suchen, bis die Summe zu groß wird. Dabei habe ich selbst bemerkt, dass eine HashMap gar nicht sortiert ist. Damit war die Idee hinfällig.
2. **Brute Force:** Für jedes i alle j prüfen, ob `nums[i] + nums[j] == target`. Das ist O(n²).
3. **Entscheidende Erkenntnis:** Wenn x und target feststehen, ist y = target − x bekannt. Die Frage lautet dann nicht mehr „Welches y passt?“, sondern „Existiert y?“. Das beantwortet eine HashMap (Wert → Index) in O(1).
4. **Handdurchlauf `[3,2,4], 6`:** Bei x = 3 ist y = 3, und die Map liefert Index 0, also das Element selbst. Treffer mit gleichem Index muss man ignorieren.
5. **Handdurchlauf `[3,3], 6`:** Zuerst dachte ich, man müsse beide Indizes speichern. Tatsächlich überschreibt der zweite Eintrag den ersten (`3 → 1`), und bei i = 0 findet man Index 1 ≠ 0. Das Überschreiben ist also unschädlich.
6. **Review:** Ohne frühes `return` lief die Schleife weiter und setzte `ans` erneut (dann mit vertauschten Indizes). Mit `return` direkt beim Fund ist das behoben, und `ans` als Variable entfällt.

### Meine Lösung

Erste funktionierende Fassung (Tests grün):

```rust
impl Solution {
    pub fn two_sum(nums: Vec<i32>, target: i32) -> Vec<i32> {
        let hashmap: HashMap<i32, usize> = nums
            .iter()
            .enumerate()
            .map(|(idx, wert)| (wert.clone(), idx))
            .collect();
        let mut ans: Vec<i32> = Vec::with_capacity(2);
        for (idx, val) in nums.iter().enumerate() {
            let y = target - val;
            if let Some(jdx) = hashmap.get(&y) {
                if *jdx != idx {
                    ans = vec![idx as i32, *jdx as i32];
                }
            }
        }
        ans
    }
}
```

Überarbeitete Fassung nach dem Review. Am Ende fehlt noch die Rückgabe nach der Schleife, also `vec![]` oder `unreachable!()`:

```rust
impl Solution {
    pub fn two_sum(nums: Vec<i32>, target: i32) -> Vec<i32> {
        let hashmap: HashMap<i32, usize> = nums
            .iter()
            .enumerate()
            .map(|(idx, &wert)| (wert, idx))
            .collect();
        for (idx, val) in nums.iter().enumerate() {
            let y = target - val;
            if let Some(jdx) = hashmap.get(&y) {
                if *jdx != idx {
                    return vec![idx as i32, *jdx as i32];
                }
            }
        }
    }
}
```

Unterschied: Die zweite Fassung braucht kein `clone()` (Pattern `&wert`), keine `mut`-Variable `ans` und bricht beim ersten Fund ab.

**Offen:** Alternative mit nur einem Durchlauf (bei Index i nur unter den bereits gesehenen Elementen nach dem Partner suchen) bewusst auf später verschoben.

### Wo ich hing

- Sortierte HashMap als Ansatz. Das habe ich selbst verworfen, weil HashMaps keine Ordnung haben.
- Die Regel „kein Element doppelt verwenden“ zuerst mit Duplikaten verwechselt. Gemeint ist „nicht denselben Index zweimal“.
- Bei Duplikaten gedacht, man müsse beide Indizes speichern. Der Handdurchlauf mit `[3,3]` hat gezeigt, dass das Überschreiben reicht.
- Zuerst `hashmap.get(val)` statt `get(&y)` nachgeschlagen, selbst gefunden.
- `Vec::with_capacity(2)` und dann `ans[0] = …`: Kapazität ist nicht Länge, Indexzugriff auf einen leeren Vec würde eine Panic auslösen. Wurde durch `vec![…]` ersetzt.
- Nicht gewusst, was nach der Schleife zurückgegeben werden soll.

### Rust-Learnings

- **`HashMap::from` vs. `collect()`:** `HashMap::from` nimmt ein festes Array von Tupeln. Aus einem Iterator von `(K, V)`-Tupeln baut man die Map mit `.collect()`. Mit `HashMap::from(iter.collect())` außenherum konnte der Compiler den Zieltyp von `collect` nicht ableiten (E0283), weil `from` viele Eingabetypen akzeptiert.
- **`enumerate()`** liefert `(index, element)`. Für eine Map Wert → Index tauscht man im `map`.
- **`iter()` liefert Referenzen** (`&i32`). Statt `wert.clone()` destrukturiert man im Closure-Muster mit `|(idx, &wert)|`, das geht bei `Copy`-Typen.
- **Ungenutzter Import** (`process::id`) wurde vermutlich von der IDE automatisch eingefügt und erzeugt eine Warnung.
- **Alle Pfade brauchen einen Rückgabewert:** Auch wenn die Aufgabe „immer eine Lösung“ garantiert, weiß der Compiler das nicht. Möglich sind `vec![]` (still) oder `unreachable!()` (lauter Abbruch, Typ `!` passt überall).
