# Lerntagebuch – 2026-10-21

## 459. Repeated Substring Pattern (Easy)

- **Muster:** String-Periodizität über Rotationen – `s` in `(s + s)` ohne erstes und letztes Zeichen suchen
- **Hinweisstufe benötigt:** 3 (Brute Force mit Teiler-Längen selbst gefunden; auf Wunsch nach besserem Ansatz Stufe 1 „Rotationen anschauen“, dann Stufe 2–3 mit dem Hinweis auf `s + s` und einer ausführlicheren Erklärung, dass jedes Fenster ab Index k die Rotation um k ist. Allgemeines Syntaxbeispiel für Slices)
- **Komplexität:** Zeit O(n) (`str::contains` nutzt den Two-Way-Algorithmus), Speicher O(n) für `s + s`
- **Status:** lokale Tests grün (7 Tests), Einreichung offen
- **Wiederholen am:** 2026-10-24, dann 2026-10-28, dann 2026-11-21

### Aufgabe

Gegeben ist ein String `s`. Lässt er sich bilden, indem man einen Teilstring mehrfach hintereinanderhängt?

**Constraints:** `1 <= s.length <= 10^4`, nur Kleinbuchstaben.

Beispiele: `"abab"` → `true` (`"ab"` × 2); `"aba"` → `false`; `"abcabcabcabc"` → `true` (`"abc"` × 4 oder `"abcabc"` × 2). Eigene Testfälle: `"a"` → `false`, `"aabaab"` → `true`, `"aaaa"` → `true`, `"abac"` → `false`.

### Kernidee (eigene Worte)

> Man verdoppelt den String hintereinander und schaut sich danach nur den String exklusive des ersten und letzten Zeichens an. In diesem Teilstring muss der originale String wieder vorkommen, damit das Ergebnis wahr ist.

**Schärfung:** Das *Warum* fehlt noch: Jedes Fenster der Länge n in `s + s` ab Index k ist die Rotation von `s` um k Stellen. `s` ist genau dann periodisch, wenn eine **echte** Rotation (0 < k < n) wieder `s` ergibt. Das Abschneiden von erstem und letztem Zeichen entfernt genau die trivialen Treffer bei k = 0 und k = n. Außerdem gilt die Aussage in beide Richtungen: kommt `s` vor, ist das Ergebnis wahr, sonst falsch.

### Weg zur Lösung

1. **Brute Force:** Präfixe als Kandidaten nehmen und prüfen, ob sie den Rest abdecken. Erste Formulierung „beim ersten Treffer den Rest prüfen“ am Gegenbeispiel `"aabaab"` korrigiert: Wenn ein Kandidat später scheitert, wird die nächste Länge probiert. Nur Längen, die n teilen, kommen in Frage.
2. **Rotationen:** Bei `"abcabc"` ergibt die Rotation um 3 wieder s, bei `"aba"` erst die Rotation um n = 3, also keine echte. Selbst gefunden: Es reicht, bis n/2 zu schauen.
3. **`s + s`:** Darin stecken alle Rotationen als Fenster. Hier hing ich zunächst und habe die Fenster nochmal rotiert, bis klar war, dass das Fenster selbst schon die Rotation ist.
4. **Zurechtschneiden:** Erstes Zeichen weg → kein Treffer bei Index 0, letztes Zeichen weg → kein Treffer bei Index n.
5. **Komplexität:** Erst O(n²) geschätzt (naiver Vergleich je Position). Mit `contains` (Two-Way) ist es linear.

### Meine Lösung

**Fassung 1** – lief, aber `remove(0)` in der Schleife macht sie O(n²):

```rust
impl Solution {
    pub fn repeated_substring_pattern(s: String) -> bool {
        let mut ss: String = s.clone();
        ss.push_str(s.as_str());
        ss.pop();
        ss.remove(0);

        if ss.len() < s.len() {
            return false;
        }
        for _ in 0..ss.len() - s.len() {
            if ss.starts_with(s.as_str()) {
                return true;
            }
            ss.remove(0);
        }
        return false;
    }
}
```

**Fassung 2** – `contains` statt eigener Schleife, O(n):

```rust
impl Solution {
    pub fn repeated_substring_pattern(s: String) -> bool {
        let mut ss: String = s.clone();
        ss.push_str(s.as_str());
        ss.pop();
        ss.remove(0);

        if ss.len() < s.len() {
            return false;
        }
        return ss.contains(s.as_str());
    }
}
```

**Fassung 3** – Slice statt `pop`/`remove`, ohne überflüssigen Wächter:

```rust
impl Solution {
    pub fn repeated_substring_pattern(s: String) -> bool {
        let mut ss: String = s.clone();
        ss.push_str(s.as_str());
        let teil: &str = &ss[1..ss.len() - 1];
        return teil.contains(s.as_str());
    }
}
```

Offene Stilideen: letzter Ausdruck ohne `return`; Verdoppeln per `s.repeat(2)` oder `format!("{s}{s}")`. Alternativer O(n)-Ansatz für später: KMP-Präfixfunktion.

### Rust-Learnings

- `String::remove(0)` verschiebt alle folgenden Bytes im Puffer nach vorn, kostet also O(n). In einer Schleife wird das zu O(n²).
- `str::contains` nutzt den Two-Way-Algorithmus und sucht in linearer Zeit.
- Slices per Range-Indexing: `&ss[1..ss.len() - 1]` ist eine geliehene Sicht ohne Kopie. Die Indizes sind Byte-Positionen, was hier wegen der reinen ASCII-Kleinbuchstaben unproblematisch ist.
- `ss.len() - s.len()` kann bei `usize` unterlaufen. Der Wächter in Fassung 1 war deshalb nötig; in Fassung 3 ist der Slice `[1..1]` bei n = 1 einfach leer.
