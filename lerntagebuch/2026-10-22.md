# Lerntagebuch – 2026-10-22

## 796. Rotate String (Easy)

- **Muster:** Rotationen über `s + s` – jede Rotation von `s` ist ein zusammenhängender Teilstring von `s + s`
- **Hinweisstufe benötigt:** 1 (Brute Force und Komplexität selbst; Längencheck nach Gegenbeispiel `"abc"`/`"abcc"` selbst gefunden; `s + s` nach der Frage, welcher einzelne String alle Rotationen enthält, selbst gefunden – die Frage war allerdings recht lenkend. Bei den Alternativen Stufe 1: `s + s` virtuell über `s[i % n]`)
- **Komplexität:** Zeit O(n) (`str::contains` nutzt Two-Way, O(n + m)), Speicher O(n) für `s.repeat(2)`
- **Status:** eingereicht und bestanden
- **Wiederholen am:** 2026-10-25, dann 2026-10-29, dann 2026-11-22

### Aufgabe

Gegeben sind zwei Strings `s` und `goal`. Gib `true` zurück, wenn `s` nach beliebig vielen Shifts zu `goal` werden kann. Ein Shift verschiebt das erste Zeichen ans Ende.

**Constraints:** `1 <= s.length, goal.length <= 100`, nur Kleinbuchstaben.

Beispiele: `"abcde"`, `"cdeab"` → `true`; `"abcde"`, `"abced"` → `false`. Eigener Testfall: `"abcde"`, `"cde"` → `false` (Teilstring, aber falsche Länge).

### Kernidee (eigene Worte)

> Die Kernidee ist, den String zweimal zu wiederholen, so kommt jede mögliche Rotation in dem String vor. In diesem String muss man nur noch prüfen, ob goal vorhanden ist. Vorher muss man noch prüfen, ob beide Strings gleich lang sind, das muss nämlich gegeben sein.

### Weg zur Lösung

1. **Brute Force:** `s` bis zu n-mal rotieren und jeweils mit `goal` vergleichen → O(n²). Bei `n ≤ 100` wäre das eigentlich ausreichend gewesen – Constraints lesen!
2. **Frühes Aussteigen:** Erst „unterschiedliche Buchstaben“ (O(n), Zusatzspeicher), dann am Gegenbeispiel `"abc"`/`"abcc"` erkannt: Die Länge ist das billigere und notwendige Kriterium (O(1)).
3. **Alle Rotationen von `"abcde"` aufgeschrieben** → alle stecken in `"abcdeabcde"`, also `s + s`, darauf `contains(goal)`.
4. **Warum der Längencheck Pflicht ist:** `"cde"` steckt auch in `s + s`, ist aber keine Rotation.
5. **Alternative ohne Zusatzspeicher:** `s + s` nur virtuell über `s[i % n]` → O(1) Speicher, aber naiv O(n²) Zeit. O(n) Zeit und O(1) Speicher gingen nur mit selbst implementiertem Two-Way – für Easy unverhältnismäßig.

### Meine Lösung

**Fassung 1** – `clone()` + `push_str`:

```rust
impl Solution {
    pub fn rotate_string(s: String, goal: String) -> bool {
        if s.len() != goal.len() {
            return false;
        }
        let mut ss: String = s.clone();
        ss.push_str(s.as_str());
        ss.contains(goal.as_str())
    }
}
```

**Fassung 2** – `repeat(2)`, drückt die Absicht direkter aus (eingereicht):

```rust
impl Solution {
    pub fn rotate_string(s: String, goal: String) -> bool {
        if s.len() != goal.len() {
            return false;
        }
        let ss: String = s.repeat(2);
        ss.contains(goal.as_str())
    }
}
```

Offene Kleinigkeit: Die Typannotation `: String` ist überflüssig, der Compiler leitet sie ab.

### Wo ich hing

- Bei der Alternative ohne Zusatzspeicher ist mir nichts eingefallen.
- Die Laufzeit von `contains` stand nicht in der Doku. Mein Bauchgefühl „O(n)“ war richtig, die Begründung fehlte (naiv wäre es O(n·m)).

### Rust-Learnings

- `str::repeat(n)` statt `clone()` + `push_str` zum Vervielfachen eines Strings.
- `String::len()` ist O(1) (Bytes, nicht Zeichen – bei ASCII egal).
- `str::contains` → `core::str::pattern::StrSearcher` → Two-Way-Algorithmus: O(n + m) Zeit, O(1) Zusatzspeicher. Garantie steht im Quellcode, nicht in der API-Doku.
- Verwandt mit 459 (gestern): Gleicher `s + s`-Trick, dort mit abgeschnittenem ersten und letzten Zeichen.
